Five ways to paint it

Same text, same card surface, one option each. On macOS the scrollbar only shows while you move, so judge it in motion — and hover it.

Native

Nothing painted. The theme only declares it is dark and the browser draws its own.

The thumb is a control: it gets dragged, hovered and pressed. Too faint and it does not read as something you can grab; too strong and it competes with the content beside it.

What is being decided is not the colour but the weight. Every option draws from the same grey ramp, so the only question is how far from the panel the thumb has to sit.

Compare the same option in light and in dark. If it vanishes in one and shouts in the other, that pair does not weigh the same in both and dark needs a pair of its own.

How far the thumb sits from its background

In the theme selected above. The reference for anything draggable is 3; below 2 it is barely there. The verdict takes the worst surface, because the thumb has to work on all of them.

What we would need to add

Tokens pointing at the ramp we already have, the way skeletons and charts do. They flip with the theme on their own: no separate dark block, no colour hardcoded.

:root {
  --scrollbar-thumb:        var(--color-secondary-l1);
  --scrollbar-thumb-hover:  var(--color-secondary-l0);
  --scrollbar-thumb-active: var(--color-secondary);
  --scrollbar-track:        transparent;
  --scrollbar-inset:        2px;
  --scrollbar-radius:       var(--rounded-full);

  /* Only needed if we decide to override the system preference.
     Setting a size is what forces the scrollbar permanently on. */
  --scrollbar-size:         12px;
}

  • Only the track is optional — the thumb is not

    The thumb is the thing you drag, so it is the one that has to clear the contrast bar. The track is decoration, and a track pinned to one panel level reads as a band on a card and disappears on the background. Dropping it means the thumb has to hold up on every surface on its own, which is what the strip above is for.

  • Thickness is the one control that costs the user's choice

    Whether the scrollbar is always there or only shows while scrolling is a system preference. Measured here: colour, hover, inset and corners on the thumb all leave it intact and reserve 0px. A single rule on ::-webkit-scrollbar — which is what setting a thickness needs — forces it permanently on and takes 12px from the content. If we want to leave the decision to the user, we ship no size.

  • Always visible does not mean a visible track

    The two are independent. Forcing the scrollbar on and leaving the track transparent gives a permanent thumb over whatever panel is underneath — the Thumb only option with Always visible. Both switches are in the toolbar.

  • The same token does not weigh the same in both themes

    The grey ramp is not an exact mirror of itself: --color-secondary-l2 reads noticeably heavier in dark than in light. We have to decide what should match — the token or the visual weight. If it is the weight, dark needs a pair of its own.

  • Firefox gets no hover

    The colours apply through scrollbar-color, but hover, inset and corners are ::-webkit-scrollbar pseudo-elements: Chrome, Safari and Edge only. Not verified here — there was no Firefox in the environment this was built in.

  • The browser still needs telling

    On top of the tokens, the theme has to declare itself dark through color-scheme. That is what fixes the scrollbars we cannot paint — native selects, third-party iframes — and the system form controls.

  • Focus cannot be painted

    No browser lets us mark the scrollbar when it holds keyboard focus. If the scrolling box is focusable, the box's own focus ring is all we get.
